# 开发规范

## OAuth 客户端与 `(-NB)` 笔记本访问

远程服务部署在 `ssh oracleg`，仓库目录为
`/home/ubuntu/siyuan/mcp/siyuan-mcp-server`，systemd 服务名为
`siyuan-mcp.service`。

`remote/server.py` 中的 `ClientAccessMiddleware` 从当前 OAuth Token 获取
`client_id`，并与环境变量 `SIYUAN_CLI_CLIENT_IDS` 比较。白名单中的客户端
使用 CLI 访问范围，可以访问名称以 `(-NB)` 结尾的笔记本。
笔记本后缀规则由 `src/siyuan_mcp_server/access.py` 实现。

### 配置步骤

1. 在发起连接的机器上确认当前 OAuth 客户端 ID。Codex 的文件式凭据存储
   位于 `~/.codex/.credentials.json`，按 `server_name` 和 `server_url`
   定位当前连接，只输出 `client_id`：

   ```sh
   python3 - <<'PYCODE'
   import json
   from pathlib import Path

   credentials = json.loads((Path.home() / '.codex/.credentials.json').read_text())
   for entry in credentials.values():
       if (entry.get('server_name') == 'siyuan'
               and entry.get('server_url') == 'https://siyuan-mcp.wenyuanxu.net/mcp'):
           print(entry['client_id'])
   PYCODE
   ```

2. 通过 `ssh oracleg` 在 `/home/ubuntu/siyuan/mcp/state/oauth.sqlite3`
   的 `records` 表中核对该 ID 对应的 `kind='client'` 记录，确认
   `client_name`、回调地址和有效期属于本次连接。

3. 将 `/home/ubuntu/siyuan/mcp/credentials.env` 备份到同目录下的
   `state/` 目录，配置文件和备份权限保持为 `600`。在
   `SIYUAN_CLI_CLIENT_IDS` 的逗号分隔列表中追加确认过的客户端 ID，
   保留已有条目。OAuth Token 与服务密钥继续保存在各自的凭据存储中。

4. 重启服务并确认状态：

   ```sh
   sudo systemctl restart siyuan-mcp.service
   systemctl is-active siyuan-mcp.service
   ```

   以状态返回 `active` 为服务恢复依据。当前 systemd 停止超时为
   90 秒，重启期间等待旧进程退出后再验证连接。

5. 使用原来的 MCP 连接调用 `find_notebooks`，确认目标 `(-NB)`
   笔记本可见，再使用其 ID 调用 `find_documents`，确认文档查询成功。
   CLI 重新注册获得新客户端 ID 后，按以上步骤更新白名单。
